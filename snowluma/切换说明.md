# NapCat → SnowLuma 切换说明

协议端换了，业务层（qqbot.*）一行没动。代码层面只加了一层 `qqbot/proto.py`，
boot / watchdog / login_qr 都改成走它，所以两个后端可以随时来回切。

## 现在的状态

| 项 | 值 |
| --- | --- |
| 后端 | `protocol_backend: snowluma`（config.yaml） |
| SnowLuma 版本 | v2.2.1 win-x64（自带 node.exe v24.22.1，不用系统 node） |
| 装在哪 | `E:\dsqq\snowluma\` |
| WebUI | http://127.0.0.1:5099/ |
| OneBot HTTP | http://127.0.0.1:3000/（token `localtoken`，同原来的 NapCat） |
| 反向 WS | 仍连 `ws://127.0.0.1:8199/onebot/v11/ws`（NoneBot 那边不用改） |
| 配置 | `snowluma/config/onebot.json`、`snowluma/config/runtime.json` |
| 日志 | `logs/snowluma.log` |

## 切换 / 回退

```yaml
# config.yaml
protocol_backend: snowluma   # 换成 napcat 就退回老方案
```

临时试一次不用改文件：`set QQ_BACKEND=napcat` 再启动。
NapCat 目录（`E:\dsqq\napcat\`）一直留着，回退不用重装。

## 换后端要做的动作

```
1. stop_all.bat                 # 关 QQ + 机器人服务（QQ 里现在挂着 NapCat 的 hook，必须先清干净）
2. 双击 snowluma\start.bat      # 或直接跑 boot.py，它会自己拉起
3. QQ 窗口会自己弹出来 → 手机 QQ 扫码登录
4. 扫码成功后 3000 端口起来 = 上线，机器人自己连上 8199
```

## 和 NapCat 的实质差别（会影响交付）

1. **没有静默登录**。NapCat 能 `launcher.bat -q <QQ号>` 直接静默登录；
   SnowLuma 只在 QQ 客户端窗口里扫码，没有 CLI / 命令登录。
   → `login_qr.py` 里 NapCat 那套「浏览器弹登录页 + 自动切扫码 + 自动刷新二维码」对
   SnowLuma 用不了，现在的实现是：拉起 QQ 窗口 + 提示人去扫 + 轮询 3000 端口。
2. **登录态靠 QQ 自己的数据**。QQ 已登录过的话，重启通常不用重扫；
   但容器/数据目录重建会换设备指纹 → 重新扫码（SnowLuma 官方排障页有写）。
3. **注入方式不同**。NapCat 自己引导 QQ 启动；SnowLuma 是 ptrace 级注入已在跑的
   `QQ.exe`，所以 `qqbot/proto.py` 里的 `ensure_qq()` 必须先确保 QQ 活着。
4. **多账号**是 SnowLuma 的强项（一个 UIN 一个 OneBot 实例，`config/onebot_<uin>.json`），
   现在这份只配了单账号，走全局 `onebot.json` 兜底。

## 风控提醒（别指望换后端降风险）

两者都是 hook 真 QQ 客户端，服务端看到的是同一个客户端，风险档位相同。
真要降风险还是老几样：专用号、独享 IP/设备、固定设备指纹（别乱重建数据目录）、
控频率、别和常用大号同机。
